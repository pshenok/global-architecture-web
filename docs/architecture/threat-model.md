# Threat model

**Assets:** access, refresh and ID tokens; the session cookie; users' data; the ability to
act as a user.

**Adversaries:** a cross-site attacker (CSRF, login CSRF, clickjacking, open redirect);
injected content (XSS); a network attacker; a compromised dependency; a contributor or AI
agent who writes unsafe code (the main risk, as in the monolith's ADR-0004); a stolen
cookie.

**Trust boundaries:** browser | Next server (proxy, Server Components, Server Actions,
route handlers) | monolith API (the authority) | identity provider.

| #   | Guarantee                                                                                     | Enforced by                                                                                                                                          | Proven by                                                                                                                             |
| --- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| G1  | Tokens never reach the browser                                                                | tokens only in the sealed session; an opaque `Caller` (token in a WeakMap); `server-only` on every server module; client files import no server code | check-boundaries R6/R7/R10, check-access S8, `next build`, e2e `session.spec` (decrypts the cookie, scans every response and storage) |
| G2  | Tokens go only to the API, the refresh token only to the IdP; public operations never get one | one outbound chokepoint (origin allowlist, no redirects, no cache); the client guard derived from the OpenAPI document                               | `outbound.spec`, `client.spec`, check-boundaries R9                                                                                   |
| G3  | No CSRF                                                                                       | the proxy refuses unsafe methods unless `Origin` equals the app (missing Origin refused) before any session work; SameSite=Lax; POST-only logout     | `pipeline.spec`, `flows.spec`, e2e `csrf-and-headers.spec`                                                                            |
| G4  | Every Server Action authenticates, validates and maps errors                                  | only `defineAction` exports in `actions.ts`, access as an inline literal, no inline `'use server'`                                                   | check-access S4 with probes, `define-action.spec`                                                                                     |
| G5  | Pages are deny-by-default                                                                     | the proxy's gate compiled from `security/public-routes.json` (CODEOWNERS)                                                                            | `public-routes.spec` (every route in `src/app`), e2e `access.spec`                                                                    |
| G6  | Authorization comes from the API, and its answers map consistently                            | `classifyReadProblem`, `defineAction`'s mapping                                                                                                      | `interrupts.spec`, e2e 404s for foreign bookings, houses, admin pages                                                                 |
| G7  | Strict CSP with zero violations                                                               | per-request nonce + `'strict-dynamic'`, the same value on request and response; every route renders per request                                      | `csp.spec`, check-build (nothing prerendered), e2e `csp.spec` (full loads, soft navigations, dialogs)                                 |
| G8  | No open redirects                                                                             | `safeReturnTo` at login; same-site paths only in action redirects; fixed post-logout URI                                                             | `return-to.spec`, e2e `access.spec`                                                                                                   |
| G9  | Refresh races never revoke a session                                                          | refresh only in the proxy, single flight per refresh token, settled result kept 60 s                                                                 | `refresh.spec`, e2e burst of five tabs against the dev IdP's strict reuse detection                                                   |
| G10 | Session integrity, lifetime and size                                                          | JWE `dir`/A256GCM, `kid` rotation, `typ` per purpose, absolute lifetime, 3800-byte cap                                                               | `codec.spec`                                                                                                                          |
| G11 | Config and secrets stay on the server                                                         | Zod env at boot; no `NEXT_PUBLIC_`; `process.env` in one file                                                                                        | `env.spec`, check-access S7, Biome `noProcessEnv`, check-build (no secret in static assets)                                           |
| G12 | No cross-user caching                                                                         | no `'use cache'`, cache APIs or segment config; outbound `no-store`                                                                                  | check-access S5                                                                                                                       |
| G13 | Logs never hold tokens                                                                        | a field-allowlist logger; `onRequestError` drops headers                                                                                             | review of `log.ts` (primitive fields only)                                                                                            |
| G14 | Supply chain                                                                                  | pnpm 24 h release age, no exotic subdependencies, no install scripts, exact pins, SHA-pinned actions                                                 | CI `--frozen-lockfile`, `pnpm audit`                                                                                                  |
| G15 | No error leakage                                                                              | 5xx shown generically with a reference; the provider's error text never reflected                                                                    | `define-action.spec`, `flows.spec`                                                                                                    |
| G16 | Hardening headers                                                                             | `next.config.ts` headers                                                                                                                             | e2e `csrf-and-headers.spec`                                                                                                           |
| G17 | Real status codes                                                                             | lookups before streaming, no `loading.tsx` above dynamic pages                                                                                       | check-access S6, e2e 404 assertions                                                                                                   |
| G18 | The proxy actually ships                                                                      | `src/proxy.ts` with a pinned matcher                                                                                                                 | check-access S3, check-build (the build's function manifest)                                                                          |

**Residual risks (accepted, documented):** a cookie stolen before logout works until its
access token expires (keep production access tokens at 5 minutes or less); the refresh
single flight is per process; all users share the monolith's per-address rate limit.
